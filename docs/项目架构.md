# ComfyUI WebApp 项目架构

## 1. 项目定位

ComfyUI WebApp 是一组内嵌在 ComfyUI 仓库中的 WebApp 管理与任务执行模块。它围绕三件事工作：

- 将 ComfyUI 工作流保存为可重复使用的 WebApp
- 为工作流提取可编辑输入字段，并在前端渲染表单
- 以用户隔离目录为边界，提交任务、跟踪状态并下载结果

当前仓库中的实现是单服务形态：前端页面、REST API、WebApp 管理、任务提交和文件落盘都在同一套 ComfyUI 进程内完成。`app/webapp_core` 提供了抽象接口，便于后续扩展到更复杂的调度或分布式部署，但仓库内并没有独立的 Worker 进程实现。

## 2. 技术栈

### 2.1 后端

- **HTTP 框架**: aiohttp
- **执行引擎**: ComfyUI 原生 prompt/execution 体系
- **数据持久化**: 本地 JSON 文件
- **文件管理**: 依赖 `folder_paths` 管理 input/output/temp 目录
- **时间处理**: 使用北京时间生成时间戳，序列化为 ISO 字符串

### 2.2 前端

- **页面**: `web/webapp/index.html`、`web/webapp/tasks.html`
- **技术**: 原生 HTML + CSS + JavaScript
- **通信方式**: Fetch API 调用 `/api/webapp/*`

### 2.3 核心模块

- **`app/webapp`**: ComfyUI 侧适配层，负责路由、业务逻辑和目录切换
- **`app/webapp_core`**: 数据模型、抽象接口、节点映射和用户目录管理

## 3. 运行架构

### 3.1 分层结构

```
浏览器页面
  ├── /webapp/index.html
  └── /webapp/tasks.html
           │
           ▼
REST API
  └── app/webapp/routes.py
           │
           ▼
业务逻辑
  ├── app/webapp/manager.py
  ├── app/webapp/node_mapper.py
  └── app/webapp/user_directory.py
           │
           ▼
共享核心
  └── app/webapp_core/
           │
           ▼
ComfyUI 核心能力
  ├── execution
  ├── nodes
  └── folder_paths
```

### 3.2 请求主流程

1. 前端页面收集工作流或运行参数
2. 页面通过 `fetch` 调用 `/api/webapp/*`
3. `routes.py` 解析请求并识别 `user_id`
4. `manager.py` 完成 WebApp 读写、任务创建、状态持久化
5. `user_dir_manager.user_context(user_id)` 在执行期间切换目录
6. ComfyUI 执行工作流并把结果写入当前用户输出目录
7. 任务状态与输出清单写回 JSON，前端轮询或刷新读取

### 4.1 默认用户与非默认用户的差异

- **默认用户 `default`**
  - 输入目录：`ComfyUI/input/`
  - 输出目录：`ComfyUI/output/`
  - 临时目录：`ComfyUI/temp/`
  - WebApp 配置：`ComfyUI/user/webapp/`
  - 任务数据：`ComfyUI/user/tasks/`
- **非默认用户**
  - 输入目录：`ComfyUI/user/{user_id}/input/`
  - 输出目录：`ComfyUI/user/{user_id}/output/`
  - 临时目录：`ComfyUI/user/{user_id}/temp/`
  - WebApp 配置：`ComfyUI/user/{user_id}/webapp/`
  - 任务数据：`ComfyUI/user/{user_id}/tasks/`

这套结构由 `app/webapp_core/user_directory.py` 中的 `UserDirectoryManager` 统一计算。

## 5. 关键模块职责

### 5.1 `app/webapp/routes.py`

负责注册并实现 WebApp API，主要包括：

- WebApp 列表、详情、创建、更新、发布、删除
- 节点提取与节点配置保存
- 文件上传、恢复、输入文件列表查询
- 任务提交、任务列表、状态查询、取消、重试、删除、下载

所有 JSON 接口统一返回：

```json
{
  "code": 0,
  "msg": "success",
  "data": {}
}
```

下载接口直接返回二进制响应，不走 JSON 包装。

### 5.2 `app/webapp/manager.py`

这是 WebApp 模块的核心状态管理器，职责包括：

- 从磁盘加载 WebApp 与任务 JSON
- 保存和更新 `WebApp`、`TaskResult`
- 调用节点映射器生成默认字段配置
- 将提交参数写入工作流并提交到 ComfyUI 执行
- 在取消、重试、删除任务时同步清理关联文件

需要注意的当前行为：

- 删除 WebApp 只删除 WebApp 配置文件，不会级联删除历史任务
- 任务列表接口支持 `limit` 和 `offset`，其他列表接口没有分页元数据
- 创建 WebApp 接口只接收并持久化 `name`、`description`、`workflow`

### 5.3 `app/webapp/node_mapper.py`

负责把 ComfyUI 工作流中的可编辑字段提取为 `NodeField` 列表，并在创建 WebApp 时生成默认配置。前端“创建 WebApp”流程和 `/api/webapp/extract-nodes` 都依赖这个模块。

### 5.4 `app/webapp/user_directory.py`

这是 ComfyUI 侧的适配入口，使用 `folder_paths.get_user_directory()` 作为用户根目录，并把目录切换委托给 `webapp_core.UserDirectoryManager`。

### 5.5 `app/webapp_core`

该目录当前以仓库内模块的形式使用，包含四类核心能力：

- **数据模型**: `WebApp`、`NodeField`、`TaskResult`
- **抽象接口**: `IPathManager`、`ITaskQueue`、`IExecutionEngine`、`INodeRegistry`
- **节点映射**: 通用字段提取能力
- **目录隔离**: 用户目录计算与上下文切换

其中 `ITaskQueue`、`IExecutionEngine` 等接口体现了未来可扩展性，但仓库当前没有落地的独立 Master/Worker 运行时。

## 6. 数据模型

### 6.1 WebApp

`WebApp` 代表一个可运行的工作流应用，核心字段包括：

- `id`
- `name`
- `description`
- `workflow`
- `nodeInfoList`
- `status`，当前实际使用值为 `draft` 和 `published`
- `tags`
- `cover_image`
- `run_mode`
- `created_at`
- `updated_at`

### 6.2 NodeField

`NodeField` 描述前端暴露给用户的单个输入项，常见字段包括：

- `nodeId`
- `nodeName`
- `fieldName`
- `fieldValue`
- `fieldType`
- `displayName`
- `description`
- `fieldData`
- `required`
- `editable`
- `fileContent`
- `originalFilename`

### 6.3 TaskResult

`TaskResult` 用于保存一次任务执行状态，主要字段包括：

- `taskId`
- `webappId`
- `webappName`
- `status`
- `nodeInfoList`
- `outputFiles`
- `error`
- `failedReason`
- `created_at`
- `started_at`
- `completed_at`
- `parentTaskId`
- `retryCount`
- `tempFiles`

## 7. 前端页面结构

### 7.1 `index.html`

提供 WebApp 管理与运行入口，包含：

- 用户 ID 输入框
- WebApp 列表与状态筛选
- 创建 WebApp 弹窗
- 编辑 WebApp 弹窗
- 运行 WebApp 弹窗

当前页面支持：

- 上传或粘贴工作流 JSON
- 自动提取节点字段
- 编辑 WebApp 名称、描述、标签与节点配置
- 发布 WebApp
- 提交运行任务并跳转到任务监控页

当前页面未提供：

- 取消发布按钮
- 封面图片编辑入口

### 7.2 `tasks.html`

提供任务监控与批量操作能力，包含：

- 用户切换输入框
- 状态筛选、应用筛选、关键字搜索
- 任务统计卡片
- 任务参数展开
- 错误信息展开
- 批量删除与批量下载
- 单任务重新运行、取消、删除、下载全部

## 8. 多用户隔离设计

系统通过以下优先级识别用户：

1. 请求头 `X-User-ID`
2. 查询参数 `user_id`
3. 默认值 `default`

目录隔离通过 `user_context(user_id)` 完成。进入上下文后，`folder_paths` 的 input/output/temp 会临时切换到目标用户目录；退出后恢复原始目录。

这意味着：

- 同一套 API 可以服务多个用户
- 上传文件、执行输出和任务 JSON 都按用户分开保存
- 默认用户与 ComfyUI 原生目录直接复用

## 9. 扩展点与限制

### 9.1 已具备的扩展点

- `INodeRegistry` 可适配不同节点注册来源
- `IPathManager` 可替换本地目录策略
- `ITaskQueue`、`IExecutionEngine` 可对接外部调度或执行层

### 9.2 当前版本限制

- 目前没有独立 Worker 进程或消息队列实现
- API 没有统一的分页对象，任务列表仅提供 `limit` / `offset`
- 删除 WebApp 不会自动清理关联任务历史
- 前端展示了运行模式选项，但创建接口当前仅持久化 `name`、`description`、`workflow`
